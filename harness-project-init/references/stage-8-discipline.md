# Stage 8: 工程纪律门禁

> 通用化自一个真实项目经两轮对抗性审查（69 条发现）+ 259 条提交考古提炼的门禁体系。
> 这些不是风格偏好——每一条都有事故实证。落地形式：写入 AGENTS.md 的门禁节 + 可选的纪律 skill + 入口文件强制引用。

## 执行时机

Stage 0-7 是一次性生成的资产；本阶段生成**门禁清单**（一次性），但门禁本身是**贯穿项目全程的执行约束**。生成后写入 AGENTS.md「工程纪律」节，并在各工具入口文件加一句「开工前先读」。

## 门禁 1：修 bug 四步，缺一步不许提交

```
① 写回归测试（先红灯）→ ② 修复（转绿灯）→ ③ 扫同类点 → ④ 落 .learnings/
```

③ 的规则：修完全局扫描同类模式；还有剩余 → 要么一起修，要么在 ISSUES.md 记「已知剩余 N 处，本轮不修」，不许默默留着。

> 实证：一个 `with ThreadPoolExecutor` 的超时失效陷阱修了 3 次仍第 4 次复发——每次都只修被点名那一处，没人扫同类点。

## 门禁 2：文档动作 ≠ 修复

以下行为一律判定为「未修复」，不许标记完成：

1. commit 声称改了代码，但 `git show --stat` 零行代码改动
2. 改注释/docstring 使其「与行为一致」，行为本身没改
3. 把教训写进文档就算修完了

自检句：**我的 diff 里有没有改变运行时的代码行？没有就是没修。**

## 门禁 3：验证靠「跑」，不靠「读」

| 改动类型 | 必做的验证 | 为什么读代码不够 |
|---|---|---|
| 全局状态（env / 类级缓存 / 单例） | 跑全量测试，不能只跑单文件 | 单看正确，一起跑才炸 |
| 配置↔代码映射（YAML/JSON↔registry） | 写脚本交叉比对 | 人工比对必然漏 |
| 数学/统计/归一化 | 已知输入算已知输出 | "看着像对的"不是验证 |
| 脚本比对出的结论 | 回读代码确认再报 | 脚本会假阳性 |

## 门禁 4：提交前自检清单（按项目裁剪后写入 AGENTS.md）

- [ ] 非空校验：diff 里有代码改动吗（门禁 2）
- [ ] 同类扫描：跑过了吗？剩余几处记了吗（门禁 1）
- [ ] 验证命令：能给一条可复现的验证命令 + 期望输出吗（门禁 3）
- [ ] 用户可感知：这个改动用户跑起来看得到吗；看不到的如实说明
- [ ] 文档同步：改行为了吗 → 相关文档/手册跟了吗
- [ ] 教训落库：本次教训进 `.learnings/` 了吗
- [ ] skill 同步：改了 skill 主副本 → 跑 sync 脚本了吗（门禁 7）

## 门禁 5：第三轮失败原则（防兔子洞）

同一方向调 2 次无显著改善 → 第 3 次停手，换方向或质疑架构。配套规则：

- 改善要有噪声门槛：低于门槛的"改善"不算成功、不进 commit
- 必须设对照（同期同条件 A/B），只看绝对值 = 把噪声当成功
- 单样本无发言权，组级统计才有结论权

## 门禁 6：harness 假设衰减审查

> 信源：Anthropic《Scaling Managed Agents》(2026-04-08)。harness 里编码着「模型不能自己做 X」的假设，模型升级后护栏会过时：为旧模型加的上下文重置逻辑，在新模型上成了无用负担。

项目动作：每次主模型大版本升级、或重要依赖升级后，重读本项目的门禁/护栏清单，删掉已过时项。说不出「现在还防着什么事故」的护栏就退休。

## 门禁 7：多工具 skill 目录同步

不同 Agent 工具的 skill 目录**互不兼容**：

| 工具 | 自动发现的 skill 目录 |
|---|---|
| Claude Code | `.claude/skills/` |
| GitHub Copilot | `.github/skills/` |
| Cursor | `.cursor/rules/` |
| Codex | `.codex/skills/` |

> 实证：某项目把「失败后必须走 self-improvement」的强制规则只放在 `.github/skills/`，而实际干活的工具不扫那个目录——这条规则从未被执行过一次。

做法：

1. 主副本放项目根 `skills/<name>/SKILL.md`（工具中立，任何工具都能读）
2. 各工具目录放同步副本，一键同步脚本（生成到 `scripts/sync-agent-skills.sh`）：

```bash
#!/usr/bin/env bash
set -euo pipefail
SRC="skills"                     # 主副本目录
DESTS=(".claude/skills" ".github/skills" ".codex/skills" ".cursor/rules")
for skill in "$SRC"/*/; do
  name=$(basename "$skill")
  for dest in "${DESTS[@]}"; do
    mkdir -p "$dest/$name"
    cp -r "$skill." "$dest/$name/"
  done
done
echo "synced: $(ls "$SRC")"
```

3. **兜底（最重要）**：在各工具入口文件（AGENTS.md / CLAUDE.md / copilot-instructions.md / .cursorrules）写死一句「开工前先读 `skills/<name>/SKILL.md`」——入口文件的覆盖面远大于 skill 目录自动发现

## 关键原则

- 每条门禁都要能回答「没有它会出什么事故」；答不出的门禁删掉
- 门禁写进入口文件才有执行力（skill 目录自动发现不可靠）
- 门禁随模型能力升级定期瘦身（门禁 6）
