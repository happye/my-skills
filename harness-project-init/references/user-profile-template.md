# 用户协作偏好资产

> 在 Step 0 收集，产出两处：项目 AGENTS.md「协作约定」节（随仓库走、团队共享）+ 用户级工具记忆（跨项目复用）。
> 目的：让每个新项目从第一天起就按用户习惯交付，而不是每次重新磨合。

## Step 0 追加询问（默认值来自用户既有偏好，整块一次性确认，不要挤牙膏式逐条问）

| # | 问题 | 用户既有默认值 |
|---|---|---|
| 1 | 交流语言 | 中文（代码注释随周围密度） |
| 2 | 交付标准 | 诚实交付 + 可感知改动：不许"看不见的改动"，局限如实标注，不假装覆盖 |
| 3 | 验证纪律 | 改动必须跑真实验证（跑 CLI 就真跑、改 UI 就用预览工具验）；跑不了的明说没跑什么 |
| 4 | 分析类输出 | 全量输出不截断（AI 推理/来源保留）+ 落盘报告（`日期_主题` 命名）方便回看 |
| 5 | 推送策略 | 已授权任务完成 + 验证后直接 commit + push，不问"要不要推送" |
| 6 | 修复风格 | 结构化锁死病根：回归测试 + 同类扫描；拒绝绕过调用点的补丁 |
| 7 | 改动哲学 | 防矫枉过正：动手前先想会不会误伤已跑通逻辑；系统级信号不解决局部问题 |
| 8 | 指令解析 | 混合指令先分类（「给 agent 的操作」vs「产品功能」），被纠正后简短复述再继续 |
| 9 | 重大动作 | 先计划确认再动手（plan mode）；破坏性/不可逆操作必须问 |
| 10 | 边界审视 | 闭区间边界值是 bug 高发点（0/极端值的语义要审视）；改计算逻辑必须失效缓存 |

## 产出物 1：AGENTS.md「协作约定」节（模板，按确认结果裁剪）

```markdown
## 协作约定

- **语言**：会话用中文；commit message 中文且详细；代码注释随周围密度
- **交付**：完成 = 验证过。没跑的检查明说；不做"看不见的改动"；局限如实标注
- **报告**：改了什么 / 为什么 / 怎么验证的，三项齐全；发现的问题直说，不粉饰
- **推送**：已授权任务验证后直接 push，不询问
- **修复**：先立病根假设 → 最小改动验证 → 扫同类点 → 落 .learnings/（见「工程纪律」节）
- **防过度**：修 bug 前先想会不会误伤已跑通逻辑；测试先行而非事后补
```

## 产出物 2：用户级工具记忆种子（Claude Code 示例，写到 `~/.claude/projects/<项目>/memory/`）

`user_profile.md`：

```markdown
---
name: user-profile
description: 用户画像与协作风格
metadata:
  type: user
---
中文交流；重诚实交付与可感知改动；会犀利质疑技术合理性——交实底比漂亮话重要。
```

`feedback_honest_delivery.md`：

```markdown
---
name: feedback-honest-delivery
description: 诚实交付与可感知原则
metadata:
  type: feedback
---
不许"看不见的改动"；每个改动用户可感知，或如实说明局限。
**Why**: 假装完成比不完成伤害更大。
**How to apply**: 交付前自问"用户跑起来能看到什么变化"；答不出就补验证或明说。
```

第三条按项目性质写（`feedback_push_without_asking` / 项目方向 / 领域红线）。每条写完在 `MEMORY.md` 索引加一行指针。

## 使用说明

- 默认值来自该用户跨项目沉淀的偏好；**换客户 / 换团队时逐项重新确认**，不要静默沿用
- 写入用户级记忆的条目跨项目复用（跟人不跟仓库）；写入 AGENTS.md 的条目随仓库走（跟仓库不跟人）
- 项目推进中的新反馈随时按 Stage 7 的记忆纪律补充，不等到收尾
