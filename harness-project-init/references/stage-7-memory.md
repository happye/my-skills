# Stage 7: 记忆资产

## 目标

让项目拥有「跨工具、跨机器、跨会话」可靠的知识沉淀层，并在项目第一天就种下正确的记忆结构。没有沉淀层的项目，每个新会话都在重交学费。

## 两层记忆架构

| 层 | 位置 | 跨工具 | 进版本控制 | 用途 |
|---|---|---|---|---|
| 仓库内学习库 | `.learnings/LEARNINGS.md` + `.learnings/ERRORS.md` | ✅ | ✅ | **唯一可靠沉淀点，必写**。教训、失败复现条件、根因与防复发措施 |
| 工具自带记忆 | 如 Claude Code 的 `~/.claude/projects/<项目>/memory/`（含 MEMORY.md 索引） | ❌ 单工具 | ❌ | 单工具内的用户偏好、项目方向等便利信息 |

**铁律：只写工具自带记忆 = 等于没写**（换工具 / 换机器 / 清缓存即归零）。工具记忆只放「服务该工具的便利信息」；一切必须长期存活的教训都落 `.learnings/`。

> 实证（来源项目 2026-08-29 审计）：`.learnings/` 停更一个月期间，两轮对抗审查的 69 条发现零条入库，23 条教训里 13 条永远 pending；同期写在工具记忆里的条目随会话丢失。

## 初始化动作清单

1. 创建 `.learnings/`：
   - `LEARNINGS.md`：表格式流水（ID | 日期 | 类别 | 教训 | 根因 | 防复发措施 | Status）
   - `ERRORS.md`：失败记录（现象 | 复现条件 | 根因 | 修复 | 验证命令）
2. 在 AGENTS.md 增加「记忆纪律」节：
   - 会话收尾：新教训 → LEARNINGS.md（必做）；有失败/复现条件 → ERRORS.md
   - 教训必须带「防复发措施」——只写「以后注意」= 没写
3. 种下工具记忆（以 Claude Code 为例）：
   - `MEMORY.md` 索引：每条记忆一行指针，不放内容
   - 首批种子 3 条（模板见 `user-profile-template.md`）：用户画像（user）、协作反馈（feedback）、项目方向（project）
4. 在入口文件（AGENTS.md / CLAUDE.md）写明收尾动作，让「沉淀」成为流程而非自觉

## 记忆写入手法（工具记忆通用）

- 一事一文件 + frontmatter（name / description / type: user | feedback | project | reference）
- 更新已有文件 > 新建重复文件；发现写错的记忆直接删除
- 相对日期一律转绝对（「上周」→「2026-09-08」）
- 正文用 `[[name]]` 互链相关记忆；索引与内容分离

## 记忆与 harness 的衰减审查

> 信源：Anthropic《Scaling Managed Agents》(2026-04-08)——harness 与记忆都在编码「当时为真」的假设；模型升级、架构演进后，旧护栏会从保护变成负担。

- 维护期（Stage 6）每月一次：抽查 LEARNINGS.md 的 Status=pending 项与工具记忆中的 project 类条目，过时的标注或删除
- 触发器：主模型大版本更换、重大架构迁移、harness 规则变更后，重读相关记忆与门禁
- 判断标准：一条记忆/护栏若说不出「现在还防着什么事故」，就该退休

## 关键原则

- 教训必须带防复发措施；「以后注意」不是措施
- 仓库内 > 工具内：能进 `.learnings/` 的不放进工具记忆
- 索引与内容分离，一事一文件
- 记忆也会腐烂——衰减审查是记忆体系的一部分，不是可选项
